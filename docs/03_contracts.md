# 03 · Contracts (freeze these before parallel work starts)

These contracts let work packages run in parallel without stepping on each other. **Change them only in WP0's PR,
or in a dedicated "contract change" PR that every open WP rebases on.**

Placeholders: `{cat}` catalog, `{studio}` app schema, `{prefix}` team schema prefix (ends with `_`), `{team}` team id,
`{root}` workspace root folder (`/Workspace/Shared/<engagement_id>`).

> **Revision 2 (23 Nov, after the stress-test review).**
> - The kit's **proven notebooks run as the jobs**; nothing is ported.
> - Storage stays **per team**, so the app and the notebook fallback share files and results. The app reads results through **union views**.
> - App state uses **3 generic tables**.
> - Task 4 runs against a **separate team rules config**.
> - Approvals are rows plus the classroom toggle. **No YAML is patched by the app.**
> - **The client never sends table names.** Analytics **cache is off**.

## 1. Engagement pack (`pack.json`)
The app is generic. Everything customer-specific comes from `pack.json` (plus files beside it) in the **pack volume**
(`DATABRICKS_VOLUME_PACK`). The schema is `pack/pack.schema.json`, and a fictional example is `pack/example/pack.json`.
- The server loads it at start-up, validates it (Zod mirror in `shared/pack.ts`) and caches it.
- It exposes only the public parts, via `/api/me`.
- The facilitator can reload it.

Key sections:
- `engagement`, `workspace`.
- `teams[]` (include a `rehearsal` test team), `demo_team`.
- `dataset` (logical → physical **templates**, expanded only on the server).
- `manifest` (team files), `recon` (layer map + `expected_scorecards`: `baseline`, `recheck_as_built`, `after_fix`, `prove_clean`, `prove_fault`).
- `faults`, `rule_templates` (Task 4).
- `agenda`, `tasks`, `rules_contract`, `lineage_template`, `prompts`.
- `questions`, `findings`, `outcomes`, `pipelines_landing`, `closeout_questions`, `pilot`.
- `genie_migrate`, `genie_spaces`, `assistant`, `estate`, `features`.

The app's server writes team files through the **Databricks SDK Files API as the app SP**, to the volume path of the
caller's own team only. **One in-flight job run per team** is enforced in `/api/recheck` and `/api/prove`.

## 3. Studio schema (Delta, `{cat}.{studio}`): app state + read views
Three append-only tables. Writes are INSERT only. `id` is a Node UUID; `ts` is naive UTC.

| Table | Columns |
|---|---|
| `entries` | `id, ts, team_id, user_email, kind STRING, entry_key STRING, payload STRING (JSON), deleted BOOLEAN` |
| `events` | `id, ts, team_id, user_email, event_type STRING, task_id STRING, payload STRING (JSON)` |
| `requests` | `id, ts, team_id, user_email, run_label STRING, job_key STRING, job_run_id BIGINT, kind STRING, params STRING (JSON)` |

`kind` ∈ `roster | lineage_row | rule_decision | classification | approval | question_answer | finding_decision |
closeout_answer | pilot_plan | estimate | agenda | task_progress | classroom_toggle`. `entry_key` is the natural key within
(team, kind), for example the row key, rule key or check name.

Views:
- **Generic:** `latest_entries` = `QUALIFY row_number() OVER (PARTITION BY team_id, kind, entry_key ORDER BY ts DESC) = 1 AND NOT deleted`.
- **Typed, for Genie and charts:** `v_classifications`, `v_rule_decisions`, `v_lineage_rows`, `v_question_answers`, `v_findings_decisions`, `v_task_progress`, `v_time_per_step` (`from_json` over `latest_entries`).
- **Results union views** (generated by `scripts/refresh_union_views.sql` after every provisioning):
  - `v_check_results`, `v_run_log`, `v_mismatch_samples`, `v_ai_explanations`, `v_run_artifacts`.
  - Each is a `UNION ALL` over every team prefix in the pack, adding `'{prefix}' AS target_prefix` where the table lacks it.
  - **Pre-create empty `run_artifacts` and `ai_explanations` in every team's `recon` schema** (they only appear after the first recheck), or the view breaks.
- **Data views** (stable tables only; never team-editable views): `v_team_tables_counts` (row counts per team per logical table) for the board.

Gotchas:
- `uuid()` is not allowed inside `INSERT … VALUES`.
- Stamp naive UTC.
- **typegen DESCRIBEs every query at prebuild**, so all DDL and views must exist first (WP0 creates them, including union views over the `rehearsal` and `demo` prefixes).

## 4. Run identity and job contract
- Every trigger uses a unique `run_label = app_{team}_{kind}_{yyyyMMddHHmmss}_{rand4}`, passed as a job parameter.
- Results are found with `v_run_log WHERE run_label = :run_label`. **Never use "latest" for a gate or a pass/fail claim.**
- UI states per request:

| State | Condition |
|---|---|
| `queued` / `running` | Job run in progress |
| `artifact_error` | Job failed with "recheck REJECTED" or a save-validation error |
| `gate_rejected` | The gate task failed, or `n_blocking > 0` with `gate=true` |
| `passed` | Finished, `n_blocking = 0` |
| `infra_error` | Any other failure |

`/Workspace/Users/<sp-id>` folder: notebook 01 extracts its kit under the running identity.

Provisioning and reset happen via the CLI today, so the facilitator console is read-only. Provision/reset buttons are Tier C.

## 8. Frontend structure and ownership
```
app/client/src/pages/registry.ts        WP0 (one lazy entry per page id; stub page per id)
app/client/src/pages/<page>/index.tsx   page owner
app/client/src/components/common/*      WP0: Loading, EmptyState, ErrorState, StatusChip, AiBadge, ProvenanceChip, CodeView, Section

app/client/src/lib/{api.ts,team.tsx,poll.ts,format.ts}   WP0 (poll.ts = recheck/prove poller + state mapping §4)
app/server/routes/index.ts              WP0
app/server/routes/<area>.ts             area owner: me, entries, events, teamfiles, jobs, migrate, draft, export, data, fac
app/shared/{pack.ts,expand.ts,ids.ts,state.ts}           WP0
app/config/queries/<page>_<thing>.sql   page owner (static SQL; params only for values, never identifiers)
```
- **Caching:** disable AppKit caches (`createApp({ cache: { enabled: false } })` or the documented equivalent; verify in the installed docs). The jobs plugin's `getRun` cache (60 s) is not used for polling: the poller calls the Jobs API directly.
- **Typegen:** after merges, run `npm run typegen`; never hand-merge `appKitTypes.d.ts`.

## 10. Server routes (`/api/*`, Zod-validated; writes as the SP; team = caller's roster team)
| Route | Method | Body / query | Notes |
|---|---|---|---|
| `/api/me` | GET | — | `{email, team_id, prefix, role, is_facilitator, features, pack_public}`. Table names are never sent |
| `/api/entries` | POST | `{kind, entry_key, payload, deleted?}` | the generic register write; `kind` allow-listed |
| `/api/events` | POST | `{event_type, task_id?, payload}` | audit + time per step |
| `/api/teamfiles` | GET | — | list the team's `team_work` with SHA-256 and provenance |
| `/api/teamfiles/:name` | GET / PUT | `{content, source}` | PUT validates by manifest kind. **A `view_sql` file must parse as exactly one `CREATE [OR REPLACE] VIEW` statement and nothing else.** Writes `.meta.json` provenance |
| `/api/drafts` | GET / POST | `{name, content, source}` | drafts and imports; never executed |
| `/api/recheck` | POST | `{apply_accepted?}` | one in-flight run per team. Triggers the recheck job (notebook 01, `mode=recheck`, `gate=false`, `ai_explain=false`, `approval_mode=classroom`, `run_label`) |
| `/api/prove` | POST | `{template_ids[], params, fault_id \| null}` | writes `team_rules.recon.yml` from vetted templates. Triggers the prove job (validate-dataset notebook, `config` = team rules file, `vars` → clean tables or the pre-created fault views, `gate=true`, `run_label`) |
| `/api/jobs/:job_run_id` | GET | — | short poll → state per §4 |
| `/api/genie-migrate/out` | GET | — | list `{root}/teams/{team}/genie_out/` (Workspace API, SP) |
| `/api/genie-migrate/import` | POST | `{path}` or `{name, pasted_sql}` | into drafts with provenance `genie_migrate` (or `pasted`) |
| `/api/draft` | POST (streams) | `{source_path, target}` | serving call with SKILL.md as the system prompt; streamed; bounded input; provenance `assistant_draft` |
| `/api/data/:logical` | GET | `?limit=` | allow-listed sample rows from the caller's team table |
| `/api/classroom` | POST | `{on}` | sets the team's classroom toggle; unlocked only when every redesign-class check is classified |
| `/api/export` | GET | — | the team evidence pack (markdown + CSV); a copy goes to exports |
| `/api/fac/*` | GET | — | `board`, `health` (read-only); `reload-pack` (POST) |

Provenance sidecar `<name>.meta.json`: `{source: seed|team_edit|genie_migrate|pasted|assistant_draft|prepared_example, saved_by, ts, sha256}`.
