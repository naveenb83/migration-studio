**Where:** the **private workshop kit** on the build machine (path in `local/LOCAL_CONTEXT.md`). Exact files, line

## Principle: reuse, don't port
The kit's attendee notebook (recheck mode) and validate-dataset notebook are proven: golden numbers and the gate on the exact run were both rehearsed.
- The app triggers **those notebooks as job tasks**, on the **same per-team files and results**.
- If the app fails mid-session, teams carry on in the notebook with nothing lost.

## Step 0 (5 minutes)
Commit the current kit state locally and tag `fallback-2026-11-24`. Never push the kit.

## Changes
1. **Attendee notebook: add `run_label`.**
   - Add an optional `run_label` widget (default blank = the old auto label) in the notebook generator. Use it as the validation label.
   - Regenerate `dist/`. Re-run one fallback smoke to prove the behaviour is unchanged.
2. **Recheck job** (`job-recheck`).
   - One notebook task running the attendee notebook with `mode=recheck`, `catalog`, `prefix`, `run_label`, `gate=false`, `ai_explain=false`, `approval_mode=classroom` and `apply_accepted` (from the app's classroom toggle).
   - `run_as` the **least-privilege job SP**. `max_concurrent_runs` ≥ 8; queue on.
3. **Prove job** (`job-prove`).
   - One task running the validate-dataset notebook, with `config` = the team's `team_rules.recon.yml`, `vars` (clean tables, or one fault view), `run_label`, `gate=true`, `approval_mode=classroom`, and results into the team's `recon` schema.
   - Same `run_as` and concurrency as the recheck job.
4. **Fault views.** One per fault kind per team (e.g. `{cat}.{prefix}faults.v_<fault>_*`).
   - Each is a view over the team's current tables applying one deterministic mutation: wrong id, wrong value, deleted record, or corrupted consumer value.
   - Created by a small kit notebook run once per prefix.
5. **Rule templates.** 3 vetted rule templates + 1 key check, in the pack (`rule_templates`).
   - The parameterised SQL uses the `${…}` placeholders that `vars` overrides.
   - Choose rules that pass on the as-built candidate, so Task 4 doesn't depend on Task 3 progress.
   - **Verify the clean × fault matrix today** and record it as `prove_clean` / `prove_fault` in the pack.
6. **Provisioning** (CLI, today).
   - Run the attendee notebook's guarded `build` mode (it seeds team_work) for every team, `demo` and `rehearsal`, in parallel.
   - Use the existing rehearsal job definition if its paths are current; fix them if stale.
   - Then: fault views, empty `run_artifacts`/`ai_explanations`, the union-view refresh (WP0 SQL), `genie_in/` publish + `genie_out/` creation with ACLs, and team group grants.
7. **Prepared assets** (today).
   - A prepared Genie-Migrate-style conversion of the selected legacy objects, labelled as prepared.
   - Baseline AI explanations, generated once per team prefix so Validate has them without AI at run time.
8. **Security fixes.**
   - Remove the answer-key table from attendee builds. The answer key stays on the demo prefix and facilitator only.
   - Confirm the job SP has no admin rights and can only touch the workshop catalog.
9. **The private `pack.json`.** A draft already exists at `pack/pack.json` in the kit, generated by `pack/build_pack_json.py`. Complete the TBD fields, add `rule_templates` and the Prove scorecards, then validate against `pack/pack.schema.json` and upload.
